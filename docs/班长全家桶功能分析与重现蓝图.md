## 1. 能搬什么、不能搬什么（决定成败的边界）

节点包约 100 个对外节点。按"能否脱离 ComfyUI 网页端"分成三类：

| 类别 | 说明 | 处理方式 |
|---|---|---|
| **A. 状态容器 / 交互面板** | CSGlide 导演台、媒体架、文案台、视觉加载器、LoRA 管理器、内存监视器、忽略编组等。核心是前端 JS 面板 + 一个 JSON 字符串 widget | **完全可搬**：在 React 里复刻面板，维护同一份 JSON 契约，提交时注入工作流 |
| **B. 参数型节点** | 放大、插帧、超分、VAE 解码、SLA 注意力、显存守卫、Sigma 曲线、视频合成等。widget 是标量/下拉 | **完全可搬**：做成 React 表单，值注入 API 工作流对应节点 |
| **C. 推理 / 引擎节点** | 真正的 PyTorch/VAE/CUDA 计算、HTTP 路由、磁盘段落档案 | **留在 ComfyUI 后端**：镜序工坊只负责发参数和收产物，不重写算法 |

**结论**：用户要的"全部搬到软件里"，正确落法是**搬 A + B 的界面与编排，C 仍由 ComfyUI 执行**。这不是妥协——这正是镜序工坊现有架构（ComfyUI 当黑盒后端）的自然延伸。试图把 C 用 TS 重写（如 VAE 编码、SLA 注意力）既不可行也无必要。

## 3. 核心：三大数据契约（重现 CSGlide 的关键）

CSGlide 把"人在网页端的操作"全部收敛进 **三个单行 STRING widget**，后端各自做白名单解析。这是整个重现工作的地基。

```
媒体架 rack_data  →  文案台 desk_data  →  导演台 h3_data
 (H3_REFS,AUDIO)     (H3_REFS,STRING)      (8 个输出)
  参考素材透传        参考素材+提示词         编码成 conditioning
```

三条铁律：
1. **单行 STRING 承载状态**：三者都是 `("STRING", {default:""})`，前端把整个 state `JSON.stringify` 塞进去。
2. **后端白名单解析**：只消费列出的字段，其余静默丢弃——前端 state 可比后端消费的多。
3. **中央库是真值，JSON 是本次提交镜像**：`csglide_store.py` 的段落档案才是段内容权威，执行时逐字段合并。

### 3.1 rack_data（媒体架）

```json
{
  "slots": {
    "images": [
      { "file": "cglide/未命名工程3/小明_正面.png", "alias": ["小明","主角"] },
      {},
      { "file": "cglide/未命名工程3/场景参考.jpg" }
    ],
    "videos": [
      { "file": "cglide/未命名工程3/运镜参考.mp4", "alias": ["运镜"],
        "start": 1.5, "end": 3.2, "audio": true, "fps": 24 }
    ],
    "audios": [ { "file": "cglide/未命名工程3/配乐.wav", "alias": ["BGM"] } ]
  },
  "fps": 24, "audio_out": 1,
  "segs": { "clip_0001": { "slots": {...}, "fps": 24, "audio_out": 0 } },
  "cur": "clip_0001", "shared": false,
  "chain": { "name": "未命名工程3", "clip": "clip_0001" }
}
```

- 后端 `emit()` 只取 `slots / fps / audio_out`，输出为 H3_REFS（JSON 字符串）+ 可选 AUDIO。
- `slots.images[N]` 的编号 N 就是提示词里 `@图片N` 的 N。空位用 `{}` 占位保持编号对齐。
- `alias`：写角色名，提示词里写角色名即可绑定（受别名模式控制）。

### 3.2 desk_data（文案台）

```json
{
  "chain": { "name": "未命名工程3", "clip": "clip_0001", "shot": "xcsyvk3" },
  "global": "现代都市，霓虹夜景，冷色调，电影感构图。",
  "segs": { "clip_0001": "@图片1中的小明走向街角。<d>我到了。</d> [镜1]" },
  "alias": false,
  "presets": ["镜头缓慢推进，主体保持在画面中央", "固定机位，人物从左侧入画"],
  "rewrite_system": "", "rewrite_model": ""
}
```

**提示词组装规则（`compose_text`）**：
- `parts = [clean(global), clean(seg)]`，**片子级在前、本段在后**，`"\n".join`。
- `presets` **不会自动拼接**——它只是文案台上可点击的快捷短语按钮，点了就追加到本段文本末尾。
- 外接提示词端口接线时，面板词完全不参与。

### 3.3 h3_data（导演台 CastCS）

```json
{
  "mode": "ref2va", "width": 928, "height": 544, "ratio": "16:9",
  "length": 719, "pin_head": 0, "pin_tail": 0,
  "ref_image_size": "match", "ref_video_size": 768,
  "ref_video_fps": 24, "ref_scale_hd": 1,
  "bridge_adapter": "", "bridge_alpha": 0, "bridge_mode": "full", "pace": 2.5,
  "prompt": "现代都市夜景，@图片1中的小明走向街角。",
  "slots": {
    "first": {}, "last": {},
    "images": [ {"file":"...","alias":["小明"]}, {}, {}, {}, {}, {}, {}, {}, {} ],
    "videos": [{},{},{}], "audios": [{},{},{}]
  },
  "cont": {"mode":"latent","latent_file":"clip_0001.t2.latent.safetensors","frames":39},
  "push_whole": false, "alias": false,
  "chain": {"name":"未命名工程3","clip":"clip_0001","shot":"xcsyvk3"}
}
```

> ⚠️ **默认值陷阱**：前端出厂 `576×320 / length 243`，后端默认 `1344×768 / length 124`。直接调后端必须**显式写全** `width/height/length`。

导演台 `build()` 输出 8 项：`正面条件 / 二采三采条件 / 潜空间 / 总帧数 / 秒数 / 重叠帧 / 整片潜空间 / 整片`。

## 4. 用户最关心的链路：参考图生成 → 绑定 → 视频提示词

这是"参考图生成之后参考图绑定的视频生成提示词"的完整端到端链路，也是重现的最高优先级：

```
[1] 参考图生成（镜序工坊已有：资产库/角色四视图/图片编辑模板）
    → 生成图落到 project media/，记为 Asset.images[]

[2] 用户选参考图 → 进 H3 媒体架
    slot.file = 相对路径；slot.alias = [资产名]
    ├─ 网页端靠 POST /upload/image 上传；镜序工坊已有上传逻辑（comfy.ts）
    └─ 写进 rack_data.slots.images[N] + h3_data.slots.images[N]

[3] 提示词绑定（核心机制：靠文本里的 @图片N，不靠连线顺序）
    ├─ alias 展开：提示词写"小明" → 自动展开成 @图片N（alias 模式开时）
    ├─ normalize_refs：<Picture>/图片N → 统一成 @图片N
    ├─ _filter_refs_by_prompt：只送提示词引用到的 @图片N（一段提几个角色送几张图）
    ├─ build_tag_map：@图片N → <Picture i>（只数已填且被引用的槽，连续排号）
    └─ transcribe_prompt：文本替换成模型协议 tag

[4] 参考图真正进入 conditioning（两条通道，缺一不可）
    ① clip.tokenize(prompt, minimax_ref_items=...)  → Qwen 视觉塔像素 + <Picture i> 锚点
    ② conditioning_set_values(cond, {"minimax_refs": ref_blocks}) → VAE 潜空间块，DiT 直看

[5] 生成视频 → 按前缀挑「三采」为最终产物（镜序工坊已有：output-files.ts）
```

**镜序工坊现状**：第 [1][2][5] 步已经打通（`workflow.ts` 的 `injectH3RefImages` 同时写 `rack_data.slots.images` 和 `h3_data.slots.images`，并把资产名写进 alias；`refAliases` 参数已接入）。第 [3][4] 步由 ComfyUI 后端的 CastCS 完成——**无需重写，只要保证写进去的 JSON 契约正确**。

**所以要补的不是算法，而是**：把"用户选哪几张图、分别叫什么称呼、提示词怎么写"这件事，做成镜序工坊里更完整、更接近导演台的交互，并确保注入的 `alias / @图片N / mode` 三态语义正确。

## 7. 风险与注意事项

1. **三态 alias**：`h3_data.alias` 缺失=开、显式 `false`=关。关闭必须显式写 `false`，否则裸角色名会被意外展开。
2. **默认值差异**：注入 H3 参数时必须写全 `width/height/length`，否则拿到后端默认值。
3. **段身份统一 `clip_XXXX`**：不要用 uid/shot id 当段身份（复制/重排后会错配）。
4. **@标签按需发送**：提示词引用哪些 `@图片N` 就送哪些；注入的槽位编号要和提示词里的 N 对齐。
5. **两条 conditioning 通道**：这是后端 CastCS 内部行为，镜序工坊不碰；只要三份 JSON 契约正确即可。
6. **Bypass/Mute 节点**：`convertUiToApi` 已跳过 mode 4/2 并做透传，不要绕开它直接提交 UI 格式。
7. **纯前端节点**：Note / Reroute / Primitive 等已被转换器丢弃，不要在新面板里试图给它们传参。
