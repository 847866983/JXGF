## 一、发布前校验流程（每次改动后必跑，全绿才发）

```bash
npm run typecheck      # 类型检查 0 错误
npm test               # 核心逻辑自检（当前 183 项）
npm run test:mcp       # MCP 项目层（7 项）
npm run test:mcp-client# MCP 全流程（8 项）
npm run build          # 渲染/主进程构建
npm run build:mcp      # MCP 单文件打包
npm run package        # NSIS 安装包
```

打包前额外注意：

1. 关掉正在运行的软件（否则 `release/win-unpacked/resources/app.asar` 被占用，打包报 `EPERM` / `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE`）。
2. 本机需 `ELECTRON_RUN_AS_NODE` 未设置（置 1 会让 Electron 以纯 Node 模式启动并崩溃）：命令前加 `env -u ELECTRON_RUN_AS_NODE`（Git Bash）或先清除环境变量。
3. winCodeSign / nsis 缓存已就位（本机打包成功过）。详见 `docs/发布与校验流程.md`。
4. 发布到 GitHub Release 需要 `GH_TOKEN`（当前环境未设置，只能出本地安装包，不能自动上传）。

## 三、待处理事项（按优先级）

### P1 — 功能缺口

1. **`aiCancel` 是死通道**：`src/shared/ipc.ts` 定义了 `aiCancel: 'ai:cancel'`，但主进程无 handler、preload 未暴露、界面无调用。
   - 影响：AI 长时间思考/批量工具调用时用户无法中断。
   - 缓解现状：底层 `fetch` 用了 `AbortSignal.timeout(180s)` 硬超时，不会无限挂死。
   - 建议做法：给 `ai-assistant.ts` 的 `chat()` 加可取消的 `AbortController`（按 providerId 或会话 id 管理），贯通 IPC 三端，界面加「停止」按钮。属于中等改动，需配套测试。

### P2 — 体验/健壮性

2. **README「已知限制」段过时**：`README.md` 末尾仍写「模型目录仅内置 Wan 2.1」「publish 为占位符」「42 项测试」等旧信息，与现状（真实 GitHub 仓库、183 项测试、多内置工作流）不符。建议随发布一并更新。
3. **H3 契约层存在未被调用的路径**：`h3-contract.ts` 的 `buildSegmentContracts()` 等在新工作流注入路径中是否全部被消费，需要一次端到端核对（当前 selftest 覆盖了主要字段注入，但契约构造器与 `workflow.ts` 实际调用链的关系建议实测确认）。此项风险中等、改动较大，不建议在发布当口动。

### P3 — 目录整洁

4. **根目录残留**：`logs/dev.log`（被安全机制拦截未删，无害）、`release/` 旧包残留（打包时会被新包覆盖）。`_backup-workflows/`、`模型库*.md`、`模型同步报告.md` 是用户数据/报告，已保留不动。
5. **scripts/ 历史脚本**：`convert-ui-to-api.mts`、`h3-e2e*.mts`、`banzhang-e2e.mts`、`import-*.mjs` 等为一次性迁移/联调脚本，不参与构建。建议归档到 `scripts/_archive/` 而非删除（保留可追溯性），非必须。
