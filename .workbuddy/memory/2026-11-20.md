## 排障：软件"打不开"（双击没反应）—— 两个叠加原因，已修复

**现象**：用户双击软件没反应。排查发现两个独立问题叠加：

1. **单实例锁卡死**：18:14 的旧实例（主 16744 + GPU/网络/渲染子进程）一直占着 `requestSingleInstanceLock()`，新双击的实例秒退、只去聚焦旧窗口；旧窗口若被最小化/卡住，用户就觉得打不开。用户确认旧窗口可关 → `Stop-Process` 全部结束释放锁。
2. **真正的启动崩溃**：从 WorkBuddy 的 Bash 环境执行 `npm run dev` 时，继承了 WorkBuddy 自身 Electron 传下来的 **`ELECTRON_RUN_AS_NODE=1`**，导致 Electron 以纯 Node 模式启动，`require('electron')` 返回的命名空间里 `app` 是 undefined → `new Updater()` 里 `electron.app.getVersion()` 抛 `TypeError: Cannot read properties of undefined (reading 'getVersion')`，主进程崩溃（日志在 out/main/index.js:3800）。

**修复**：启动前 `unset ELECTRON_RUN_AS_NODE` 即可：
```
cd "D:/镜序工坊" && unset ELECTRON_RUN_AS_NODE && npm run dev
```
**注意**：代码本身无 bug（typecheck/183 测试/build 全过）。此环境变量坑只在"从 WorkBuddy 终端代启动"时出现；用户自己双击图标不继承该变量，不受影响。以后凡是从本 agent 环境启动 Electron，都要先 `unset ELECTRON_RUN_AS_NODE`。

**结果**：清锁 + 清变量重启后，窗口"镜序工坊"响应正常、dev server 5173 返回 200、无 getVersion 崩溃。
